# Strategy Planner — editing a concept page's text: the wording

> ✅ **APPROVED BY MIKE 2026-09-25** ("yes"), as the seven pieces below, word for word.
> Item **15.25**. The working test these replace is
> [`mockups/strategy-edit-text-test.html`](mockups/strategy-edit-text-test.html), whose own labels
> ("Apply", "Close", and colour codes in its fit message) were placeholders.
>
> The build renders these through `locales/en.json`. They are not reworded there.

| Where | Wording |
|---|---|
| Heading of the edit box | Edit this text |
| Save button | Save |
| Cancel button | Cancel |
| Undo button | Put back the original |
| When the edit fits | Fits the page. |
| When it does not fit | This doesn't fit — it runs into another part of the page. Shorten it to save. |
| Small line under the box | This change is for this session only. Your firm's pages are not changed. |

**One behaviour goes with the "does not fit" line:** the part of the page the edit runs into is
outlined in red, so the advisor can see what to shorten around. The sentence deliberately names no
shape or colour: the test's version did ("circle #F47D2F"), which means nothing to an advisor.

**Why an edit that does not fit is not saved** — Mike's ruling, 2026-09-25: *"we will add the
ability to 'add a page' later on and for those who have much more, they will use the 'add a
template' function and bring in the whol thing."* A page edit is for a few words; more content has
its own route, so a messy page never reaches the client's printed plan.

**The small line** says out loud Mike's Decision C of 2026-09-21: *"The advisor edits only the
session in front of him, and his changes never become the firm's standard by accident."*
