## The finding

55 branches across 8 logic trees keep their instruction in a field called `recommendation`.
[`formatNodeForPrompt`](../server/utils/logicTrees.js#L299) reads `action` and has never read
`recommendation`, and none of the 55 has an `action` to fall back on — so **those instructions
have never reached the AI**. Verified against the data 2026-08-05: 55 nodes, 0 with a fallback,
all of node type `recommendation`.

Reading the source PDFs in `Logic Tables/` settles where the names came from:

- **The source documents are four-column IF/THEN tables.** Logic Branch · IF (Condition) ·
  THEN (Action / Next Step) · Additional Context / Notes.
- **The THEN column names the tools, in Mike's own words**, and the trees copied them
  faithfully. "THEN deploy the *Risk Mgt Cover* matrix", "THEN apply the *Ethics Conduct &
  Effect* matrix", "THEN initiate the *Directorship Pathway 1* checklist".
- So the logic tables use the **working name** — often a tab, checklist or matrix *inside* a
  document — while `search_content` publishes the **whole document** under a different title.

**The exception is the whole Get Seminar tree** — see the last section. That one really was
invented by the app layer, and is a different problem with a different fix.

**The search export is generated by the master app and is never edited here.** Every correction
below happens on our side, in `data/logic_trees.json`.

## 4. The Get Seminar tree — a different problem

`Logic Tables/Get Seminar Logic.pdf` is a seven-row IF/THEN table with **no template column, and
the word "template" appears nowhere in it**. The tree's `recommendation` field nonetheless says
*"Use Get Seminar template"* on all seven branches — the **PDF's own filename** turned into a tool
name by the app layer. "Get Team Problem" in the same tree is likewise a logic-table filename
(`Get Team Problem Logic.pdf`).

This was already recorded in
[`TREE-PDF-FIDELITY-SWEEP-2026-06-23.md`](TREE-PDF-FIDELITY-SWEEP-2026-06-23.md):

> `get_seminar` … 7 situations 1:1 + a synthetic router node; **"use X template" lines are
> app-layer (not in PDF)** but benign

It was benign only because nothing read the field.

**Nothing of substance is lost on these seven.** The PDF's THEN column — the real instruction —
went into `notes`, which *does* reach the AI:

| | |
|---|---|
| PDF, THEN column | "call out the ghosts early in the presentation" |
| `notes` — reaches the AI today ✅ | "Call out the ghosts early in the presentation — acknowledge known concerns before the audience can raise them…" |
| `recommendation` — dropped ❌ | "Use **Get Seminar** template. Address known objections at the opening of the session…" |

The dropped field is a weaker restatement plus an invented name. **Deleting it costs nothing.**

There is a real seminar template if one is wanted: **Design & Deliver**, in
*Get the Job › Seminar Delivery › Public Speaking* — *"Deliver a clear, engaging, easy-to-follow
presentation… a structured framework that sequences the presentation logically."* Three of the
seven branches are about networking rather than seminars (B3, B4, B5) and would point instead at
**My Network/Entertainment Schedule**; B6 is about facilitating a room and would point at
**Facilitation 101**.

## What happens after the rows above are settled

1. Apply the confirmed names to `data/logic_trees.json`. Nothing else changes at this stage.
2. Only then make `formatNodeForPrompt` emit `recommendation`. Doing this first would push
   unresolved names into live prompts.
3. Extend the ghost-reference validator
   ([`logicTrees.js` L65–81](../server/utils/logicTrees.js#L65)) to check names written into
   prose, not just `node.templates`.
4. A test that fails the build if a node carries a `recommendation` the prompt builder does not
   emit, so a third field name cannot repeat this silently.

Steps 2–4 are code changes and will be proposed separately, each with its own approval.
