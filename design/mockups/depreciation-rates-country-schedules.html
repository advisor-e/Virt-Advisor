3 · Reading 52 pages without asking for 52 pages at once

🔴 This section is the whole reason the item exists, and it is the fix for 4.90 and 4.91. Today one request sends the whole PDF and asks for everything back in one answer. IR265 came back with nothing. Whether the model gave up on the length or the answer was too large to finish, the cure is the same and it is not a bigger cap: ask for a page range at a time and build the table up.

Recommended: each pass names a page range, and passes are additive — a pass that fails is retried on its own and never discards the passes that worked. That is the direct lesson of 2026-09-11, when one pair of rows about undersea cable capacity on pages 39–40 threw away all 52 pages.

4 · Approving a country's table — one decision, not 2,800

A manager is never asked to check 2,800 rows, and pretending otherwise would make the approval a formality — which is worse than no approval at all. Recommended: what they approve is the schedule: this document, this edition, this country, these pages read. The table is then searchable, and anything they disagree with can be corrected in place.

7 · What this drawing deliberately does NOT do
  • It does not store the PDF. The document is sent to the model, read, and discarded — the existing rule, and it keeps path traversal, storage limits and a deletion policy off the attack surface entirely. What is stored is the table read out of it.
  • It does not replace the firm's own uploads. A firm advising a client in a country the brand has not loaded still loads its own document, exactly as approved on 2026-09-08.
  • It does not apply a rate to anybody automatically. Nothing unapproved reaches a forecast, and a firm's six rates still change only when that firm's manager approves them.
  • It does not add a seventh asset category. The forecast depreciates six; a rate stored against anything else could reach no forecast.
  • It does not let one country's table reach a client in another. A table is tagged with its country and a document published for another country is refused on load.
  • It does not make the app an authority on any country's tax law. It knows how to read a document somebody gave it and show a person what it found — including, plainly, what it did not.
8 · Three decisions this needs from Mike

Nothing is built until these are given. Each is one recommendation and one yes/no question, and they will be put to you one at a time, not as a list to answer in a batch.

Decision 1 · Does a sectioned read count against the 20-readings-a-day cap?

The cap of item 4.82 is 20 documents per firm per rolling 24 hours. A 52-page schedule is 7 model calls and a 71-page one is 9, so a global group manager loading three countries in an afternoon would spend 25 readings and be stopped part-way through a table.

Recommended: a country schedule gets its own separate allowance, counted in schedules rather than in model calls, and it does not touch a firm's 20. The reason is the point of the whole item — this is the load that stops every firm paying to re-read the same document, so charging it to a firm's daily allowance would penalise the thing we want to happen. A half-read schedule is also worse than none: it looks complete.

Decision 2 · A pass that keeps failing — stop, or store the schedule with a hole named?

If pages 41–48 will not read after a retry, there are two honest endings: refuse the whole schedule, or store the other 44 pages and say on screen that 41–48 were not read.

Recommended: store it with the gap named. It is the same judgement you already made on 2026-09-11 — a document that defeats us in one place is not a document we should throw away entirely — and 44 pages of real classes beat six app defaults. The condition is that the gap is stated wherever the table is used, never only where it was loaded.

Decision 3 · When a firm has its own approved table AND its country has a schedule

Today the nearest approved table above the client wins, so the firm's own would beat the brand's country schedule.

Recommended: leave it exactly as it is — the firm's own wins. It is the existing rule for every cascading block in the app, a firm that went to the trouble of approving its own table meant it, and changing the rule here alone would make this the one block that behaves differently. The country schedule reaches every firm that has approved nothing, which today is all of them.

Security and privacy, stated before any code is written — CLAUDE.md requires flagging this. The exposure is the same family as the firm upload approved on 2026-09-08, with one difference that makes it larger and one that makes it smaller.

  • Larger: one bad schedule reaches every firm in the brand. A firm's bad upload harms one firm. This is why loading stays at one tier, why approval is explicit, and why every rate keeps its page so a wrong figure can be traced rather than argued about.
  • Smaller: there is no personal data in this at all. A published tax schedule is a public document. No client, business or person is in the request — the prompt says so and the route sends nothing else. No exception to the stripping rule is needed or sought.
  • Identity from the verified token only. The scope comes from the existing auth, never from the browser, so one brand cannot write another brand's schedule.
  • Size cap and type check before the body is read, following the repository's own procedure for untrusted uploads, with last-known-good and version history.
  • The previous edition is kept as last-known-good, so a bad load can never leave a country with no table.
  • Nothing the model returns is trusted as structured data. Every class must carry a rate in range, a page and a label, or it is dropped — the existing bar, applied per pass.
