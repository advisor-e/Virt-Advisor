What this screen cannot do

Stated up front so it is never mistaken for a clean bill of health.

  • It cannot know a phrase is a tool. A name inside a sentence is found by looking for capitalised phrases, so it will sometimes raise something that was never a document — which is why "Not a tool" exists. It will also miss a tool written in lower case.
  • "Probably this" is a suggestion, never applied on its own. Nothing changes a logic table until you press a button. This is deliberate: on 4 August a set of these names was confidently judged missing, and that judgement was wrong.
  • It checks titles, not contents. Two templates share the title Partner Accountability and two share Quality Decisions. The screen will ask you which one you mean rather than choose.
  • It cannot publish a missing document. "Missing — flag it" records the gap for the master-app team; only they can add it to the export.

What "Apply it" does — ruled 2026-08-09

The button above was approved on 5 August; what it leads to was not decided until now. Recorded here, on the artefact it belongs to, rather than in a commit message.

🔴 RULED (Mike): it prepares a reviewed change. It never edits a table directly. Three reasons, and a live button was the obvious alternative:

  • This exact fix is already made by reviewed commit. Twice — bd7dc63 reconnected five retitled pages, and 3064a71 swapped the same five names in tree prose. This fits that practice rather than replacing it, and it is what templateCheckRulings.js already said would happen: a ruling is recorded "so it can be applied later, in one reviewed pass".
  • A stored override would fence the table in the AI prompt. Any logic table carrying an override is marked as human-edited, which makes the prompt wrap its text as untrusted. Applying rulings that way would re-tune the prompt for every firm, one table at a time, invisibly.
  • A stored override would go stale. It freezes a copy of the table, so a later improvement to the committed version could never reach anyone whose rulings had been applied.

Every prepared change is classified, and nothing awkward is dropped — a short list would read as a finished job. Ready: unambiguous. Needs checking: the name appears twice, or in two of the three sentence fields, or the branch has since changed, or the ruled template is no longer in the catalogue under that title. Two decisions correctly produce no change at all and are counted rather than lost: Not a tool (the phrase was never a document) and Missing — flag it (only the master-app team can close it).
