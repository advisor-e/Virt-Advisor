Global Group Manager Hub · Group Manager Hub

Two new pages, both rendering the same Hub component at a new scope, so that a manager at either middle tier lands on a screen that names their level and acts at it — authoring content that cascades to the firms beneath them.

0 · Why it runs in two directions — Mike, 2026-08-10

The reason behind every ruling on this page. Recorded first, because it is what settles any question §2 does not explicitly answer.

The governing principle "Every quality system requires a feedback loop, a way to make sure we can improve. The information and tools cascade down so we share the tools effectively, the reports cascade up so we learn what is working, what isn't, who is failing so we can offer help."
  • Down = sharing. One person authors a tool well, and every level below gets it without rebuilding it.
  • Up = learning. Every level sees how the level below is actually getting on, so help can be offered to whoever needs it.
  • Which is why there are no exceptions. A report withheld from a level is a hole in the loop — that level can still be held accountable for what it can no longer see. This is also why the tone throughout is offer help, not score: the same reason the adoption tab's wording was ruled warmer and advisory rather than a league table.

The first draft of this table was wrong, and this is what it got wrong. It left Team Progress, Team Case Studies and the three accuracy reports out of both middle tiers, reasoning from the 2026-08-09 ruling that kept Team Progress away from the mentor. That ruling was about an outside party — Advisor-e — seeing a customer's staff. A global group is a brand (the seeded examples are Advisor-e, BDO, Lindt & Co), so a group manager is the customer's own senior person looking at their own firms. The governing rule was already recorded on 2026-07-30 and says the opposite of what was drawn.
Why the two middle columns are identical. A global group manager and a country group manager do the same job at a different width — author content for everyone below them, and see the level below them summarised. "All of the functionality that you see at firm manager is simply repeated at group manager or global manager… there's no new functionality" (Mike, 2026-07-30).
What "summarised" protects. The rule is the level below, not everything below. A group manager's Team Progress shows their firms, not a flat list of every adviser in the country; the drill-down to a named person already exists, tier-resolved server-side, in Adviser Network. So the roll-up gets richer as it rises without any level ever being handed the raw roster of a level two below it.

3 · The trap in the existing code — read before ruling §2

This is the reason §2 has to be ruled explicitly rather than left to the code to work out.

Three tabs are currently switched on by "is this NOT the mentor?" rather than by naming the tier. The moment a third scope value exists, scope !== 'mentor' becomes true for it — so Team Progress and Team Case Studies would appear at both new tiers automatically, showing other firms' advisers by name and their case text, which is precisely the boundary ruled shut on 2026-08-09. In the same movement the Advisory Distinctions tab, gated on scope === 'firm', would vanish from the new hubs.
  • Nothing would error and no test would fail, because no test asserts what a scope that does not yet exist should show. The screen would simply be wrong in the customer's favour and against the firm's.
  • The fix is to state each tab's tiers by name rather than by what they are not, so adding a fifth scope one day cannot silently switch anything on. That is part of this build, not a follow-up.
  • This is the same failure family as the two already on record: a rule expressed as a negative that quietly changes meaning when the world grows.

4 · What was decided

Recorded here so that "approved" names something specific and checkable, rather than an event in a conversation.

Ruled by Mike, 2026-08-10

  1. 1 · EVERY REPORT ROLLS UP. Asked directly — "does the rule apply to every report on the Hub?" — answered "every report". So no report is confined to one level. Each appears at every managing tier and shows the level immediately below it, summarised. §2 is redrawn accordingly, and the reasoning that produced the first draft is recorded above it rather than quietly replaced.
  2. 2 · Page titles and addresses. Global Group Manager Hub at /global-group-manager and Group Manager Hub at /group-manager — Mike's own words for the titles.
  3. 3 · Before the master team wires the roles — FAIL CLOSED. Nobody reaches either page, and anyone who tries sees a plain message saying the level is not connected yet — not a blank screen, not a hidden 404. Letting an existing role stand in is what let a mentor's saves run into a firm's storage for weeks.
  4. 4 · A roll-up with no data SAYS SO. Never every firm, and never a silent zero that reads as "nobody is using it". This is not a new decision — it is §4.3's standing rule: "Where a stub is the honest answer, it says so on screen rather than showing an empty roll-up that looks like real data with nothing in it." It governs most of what the two new hubs will show on day one.

5 · What the master team connects — the whole of it

Written as the handover list, so it can be sent as it stands. We build everything else.

  • Two role values in the login token — one for each new hub — and, worth raising in the same breath, the mentor role that was never added and is still borrowing platform_admin.
  • Which group the person manages. Their brand, and for a country manager their country. Advisor-e already holds this shape on the user record — firm is the Advisory branch and country is country-address — so this is a claim to pass through, not data to create.
  • Nothing else. No new table, no schema change on their side, no screen. Each group also needs one reserved row in our own firms table, which is ours to create and is covered by the build.
The one thing that must not be skipped. Without the reserved row, a middle tier's saved content is refused by the database while the screen reports success — the exact trap that ran the mentor's own saves broken for weeks. The build creates the row or fails loudly; it will not be allowed to half-succeed.

6 · What will still not be proven when this ships

Written before the build rather than discovered after it.

  • Neither page can be opened by a real group manager, because Advisor-e issues no such role yet. Both will be demonstrable by tests, and openable locally in development — but not by the person they are for.
  • No firm will inherit from a middle tier until the master team says which firms sit where. Content authored at group level will be stored correctly and reach nobody. That is the honest state, and the hub should not imply otherwise.
  • The Adviser Network roll-up has never met real tier data. It is written to roll up and resolves the caller's tier server-side, but no manager above a firm has ever called it. A statement about what is untested, not a doubt about what it does.
