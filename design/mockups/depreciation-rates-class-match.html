3 · When nothing in the document fits

The system proposes nothing rather than its best guess. This is the ruling's sharp end: a category matched to a class the machine was unsure of would carry a real page number into a lender's document. An unmatched category keeps the app's default, is badged as one, and is named in the "what the AI could not find" panel the parent drawing already has.

4 · What this drawing deliberately does NOT do
  • It does not let a manager invent a rate here. This step is only about WHICH published class a category takes. Correcting the figure itself happens on the approval table in the parent drawing, where a changed rate is still the manager's and still shows its source.
  • It does not let a manager combine several classes into one category. One category, one published class, one page — so a rate on a report has exactly one thing to point at. Combining was considered and rejected on that ground alone.
  • It does not add a seventh category. The forecast depreciates six; a rate stored against anything else could reach no forecast.
  • It does not silently re-match when a new document is loaded. A confirmed match stays confirmed; a newer document changing the RATE is the parent drawing's rule 1 (newer wins, older shown beside it) and does not quietly change the class.
