3 · Why these six are one group and not two

The line that was drawn first, and why it was wrong.

The rejected split. The first draft separated “what the AI draws on” (Domain Support, Distinctions, Coaching Reference) from “how advice is chosen and delivered” (Logic Tables, Advisory Staircase, Logic-Lab). That states a falsehood. The prompt builder server/advisorEngine.js loads all six — domain support, distinctions, coaching, logic trees and the staircase. Any name implying the logic tables or the staircase are outside the AI's reach would teach every new manager something untrue, permanently, from the navigation itself.
It fails a second time on the detail. Coaching Reference is not content — its own file describes it as “the guidance the model reads when it chooses which template to put in front of a client”. That is a decision, not a thing said. The honest split is therefore two items and four, and a group of two is too thin to earn a heading.
One group of six. The true statement about all six is the same statement — everything here teaches the AI — which is the hub's own stated purpose: “The hub exists so a firm can teach the system without a developer.” It also matches the door managers arrive through: “Manage AI Coach” in the master app.

5 · A duplicate found while drawing this

Not a naming problem. Two of the fourteen tabs are the same data.

A group manager and a global group manager are shown the same cases twice.

/api/firm-manager/cases (Team Case Studies), for any tier above a firm, returns withOrigin(listSharedWithMentor(firmId), firmId).
/api/mentor/cases (Case Reviews) returns withOrigin(listSharedWithMentor(req.firmId), req.firmId).

Same store call, same decoration, same scope — the identical set of cases, in two tabs, under two different names. Only the firm manager's version differs: theirs reads their own advisors' cases in full, which is genuinely a different screen.

DECISION NEEDED. Drop “Your advisors' cases” at the group and global tiers only, leaving it a firm-manager tab, and let the roll-up version carry those two tiers. That takes them from 14 tabs to 13 and removes a contradiction, not just a crowd. The alternative — keep both — means two names for one list, which no rename can fix.

This has not been actioned. Removing a tab is the owner's call.

6 · Rules this design holds to

RuleHow this design satisfies it
Nothing moves under the owner's hand (ruled 2026-08-15) The hub menu never collapses itself. Opening Domain Support, which has its own list, does not tidy the hub menu away as a side effect. The manager collapses it, or it stays.
One screen, four tiers, no forking (Brief P1) One component still. Groups are declared once beside TAB_TIERS; a tier shows the headings its tabs fall under and no others.
Every conditional tab names its tiers positively (Brief P2) Unchanged. Grouping is a display layer over TAB_TIERS; no gate is rewritten.
Bulma + Buefy only (Stack Constitution req. 6) Buefy ships b-menu with grouped lists. No second UI library, nothing new installed.
The collapse pattern already exists Domain Support and Logic Tables already have a Show/Hide list button that remembers the choice in the browser. The hub menu reuses it rather than inventing a second one.
The tab-order trap (Brief §4, bit on 2026-08-18) Grouping reorders tabs, so mentorHubScope.component.test.js needs its list rewritten in the new draw order. Flagged here so it is expected rather than discovered.
